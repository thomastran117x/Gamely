# Security Policy

## Supported versions

Games has not published its first tagged release. Security fixes are made only on the latest
`main` branch.

| Version                    | Supported |
| -------------------------- | --------- |
| Latest `main`              | Yes       |
| Older commits and branches | No        |

## Reporting a vulnerability

Do not open a public issue, discussion, or pull request for a suspected vulnerability. Use
[GitHub private vulnerability reporting](https://github.com/thomastran117/Games/security/advisories/new)
so details can be reviewed before disclosure.

Include, when available:

- the affected component, endpoint, and revision;
- a clear description of the impact and required conditions;
- minimal reproduction steps or a proof of concept;
- suggested mitigations or fixes; and
- whether the issue has been disclosed anywhere else.

Do not include real credentials, personal data, or data obtained from systems you do not own or have
permission to test. Maintainers will coordinate validation, remediation, credit, and disclosure with
the reporter. Response and release times depend on severity and maintainer availability; no fixed
service-level commitment is currently offered.

Private vulnerability reporting must remain enabled in the repository settings. If the link above
does not offer a private report form, use a private contact method listed on the
[maintainer's GitHub profile](https://github.com/thomastran117) and do not publish the details.
